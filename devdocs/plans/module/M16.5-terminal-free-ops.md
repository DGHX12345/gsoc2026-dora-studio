# M16.5: Terminal-Free Operations（去终端化）

**Layer**: 0-1 — Foundation（生命周期 / 运行操作）
**Depends on**: M15.5（dora 1.0 环境与协议对齐）
**Effort**: 1.5 周
**Timing**: M15.6（OTLP gRPC 接收器）之后、M17（版本管理）之前；交付节奏为两个 PR（生命周期 / 录制）

> **Revision 2026-08-17**（与学生逐节确认的设计决策）：
>
> 1. **范围边界**：一次性环境搭建（Jaeger 容器、dviz 编译、moveit pip 安装）
>    **出圈**——写入 README，用户安装 Studio 时按需执行；UI 不代劳安装。
>    本轮只做 Studio 能直接控制的项：dora 生命周期、数据流生命周期、录制。
> 2. **数据流统一 coordinator**：Run Monitor 从 `dora run`（standalone，对
>    `dora list` 不可见）改为 `dora start --name` / `dora stop --name`。
>    单一事实源：Studio 起的与终端起的流量在 Dashboard/日志页全部可见可停。
> 3. **只支持 dora 1.0**：生命周期命令按 1.0 实现（up/down/start/stop）；
>    检测到非 1.x 时 `lifecycleUnavailable`，UI 禁用并提示升级。
> 4. **二进制定位**：`DORA_STUDIO_DORA_BIN` 环境变量 → PATH 回退；
>    后端启动时 `dora --version` 做版本门（复用 M15.5 D2 的缓存与归一化）。
> 5. **端点策略**：新增 `/api/session/*`；`/api/daemon/*` 保留为内部转发
>    （零破坏，前端改指向新端点）。
> 6. **录制按帧流语义设计**（学生强调：目标是接入真实机器人）：
>    .drec 每条消息 = 一个带时间戳的帧；录制 = 帧流采集，回放 = 帧级拖动
>    （ReplayTimeline/PlaybackEngine/归因链已就绪）。真实机器人数据流接入后
>    录到的即真实逐帧数据，机制不变。停止后列表显示**帧数**（截断文件用
>    扫描计数，M15.5 截断容错兜底）。录制需运行中的 coordinator，会话未启动
>    时 Record 按钮禁用并引导先 Start session。
> 7. **状态检测不依赖子进程归属**：会话状态 = coordinator 连通性（WS 已连
>    或 `dora list` 成功）——终端起的会话 Studio 同样可见、可停。

## Purpose

整个 Studio 不再需要终端完成任何日常操作：一键起停 dora 会话
（`dora up`/`dora down`）、coordinator 注册的数据流起停、帧流录制与回放。
对应「简化上手难度」的产品目标。

## Architecture

```
backend/src/dora_env.rs (新)    dora_bin() 统一解析（DORA_STUDIO_DORA_BIN → PATH）
                                版本门：dora_version() 非 1.x → lifecycleUnavailable
backend/src/session.rs  (新)    DoraSessionManager（取代 daemon.rs 的 DaemonManager 角色）
  start()    spawn `dora up`（前台挂住不等待，日志进环形缓冲）
  stop()     spawn `dora down`（1.0 语义：先停数据流再拆会话）
  status()   { running, coordinatorConnected, pid, version, dataflowCount }
             running = coordinator 连通性，不做子进程归属假设
backend/src/runtime.rs (改)     RuntimeManager 数据流统一 coordinator
  start_dataflow()  `dora start <path> --name <studio-id>`（子进程捕获 stdout/stderr）
  stop()            `dora stop --name <id>`（名字释放延迟重试）
backend/src/recording.rs (新)   RecordingController（帧流采集）
  capture()  spawn `dora record <yaml> -o <root>/out/recordings/<ts>.drec`
  stop()     终止子进程 → 截断文件（可回放）；帧数 = 扫描计数
  list()     out/recordings/ 清单（名称/大小/时间/帧数）
backend/src/main.rs   /api/session/{status,start,stop}、/api/recording/{capture,stop,list}
                      /api/daemon/* 内部转发 session
frontend/
  DashboardView.vue  Quick Start → 会话控制（Start/Stop session + 状态 pill + 版本 + 停止确认弹窗）
  RunMonitorView.vue  顶部会话状态条；行操作 Start/Restart/Stop + Record/Recording… Stop；
                      录制列表（帧数）→ Open in Replay（跳 Replay 模式自动打开）
  全局                 lifecycleUnavailable → 按钮禁用 + 「需要 dora 1.x，当前检测到 vX」；i18n 中英
```

## Risks

| Risk | Probability | Impact | Mitigation |
|------|------------|--------|------------|
| `dora up` 前台挂住、`dora down` 退出不干净 | Medium | Medium | 1.0 已实测可用；spawn 不等待；down 后轮询 coordinator 连通性确认 |
| `dora start` 同名释放延迟报错 | Medium | Low | 停止后延迟重试 + 新名字策略（0.5 踩坑经验） |
| 外部会话状态竞态（他起我停、我起他停） | Low | Medium | 状态以 coordinator 连通性为准，不做子进程归属假设 |
| 截断录制文件后续版本格式变化 | Low | Low | M15.5 截断容错 + dora10.drec fixture 已入库 |
| runtime 命令切换影响 M03-M15 演示回归 | Medium | Medium | PR 1 单独验收；B5/M15 演示在 1.0 下全链路回归 |
