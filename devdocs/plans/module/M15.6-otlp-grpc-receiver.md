## Purpose

dora 节点经 OTLP gRPC 直接推送 spans 到 Studio，火焰图（M08）变为真正的
推送模式，免 Jaeger/Collector 外部依赖。

## Architecture

```
backend/src/otlp.rs (扩展)   + ExportTraceServiceResponse {}(空消息=合法空响应)
                             + ExportMetricsServiceRequest/Response {}(stub 用,任意载荷可解码)
backend/src/otlp_grpc.rs (新) gRPC 接收器
  trait TraceService   export(Request<ExportTraceServiceRequest>) →
    spans_from_request(otlp.rs) → OtelCollector::ingest → Response<空>
  trait MetricsService export(Request<ExportMetricsServiceRequest>) → 丢弃 → Response<空>
  手写 Server 包装(TraceServiceServer/MetricsServiceServer,tonic::codegen::Service 样板,
    ProstCodec 用我们自己的 prost 0.13 类型)
main.rs   第三监听器 4317:tonic Server::builder().add_service(trace).add_service(metrics)
  .serve(addr),spawn 任务,shutdown 时 abort(与 4318 同模式)
frontend  MetricsDashboard 空状态文案 + i18n 词条(DORA_OTLP_ENDPOINT 4317 说明)
```
